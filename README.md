# 随想画卷 Persona Canvas · 0.5.11

AstrBot 角色陪伴插件：沿用当前人格与聊天记忆，让角色先决定是否愿意拍照，再执行生图、换装、参考图编辑和主动消息。包含完整的 AstrBot 内嵌管理页面。

完整版本记录见 [更新日志](CHANGELOG.md)，每次更新同步维护。

- 修复 [Issue #2](https://github.com/iownmmiku/astrbot_plugin_persona_canvas/issues/2) 的插件侧投递路径：后台图片和原图补发通过任务保存的原会话发送，不再使用已经结束的 WebChat 请求事件。

## 0.5.1 新增

- 拍摄事实记录：原生异步照片的生成、失败、取消和发送状态会进入下一轮角色上下文；聊天记录仍由 AstrBot 管理。
- 聊天中说“别拍了”或后台点击“取消拍摄”即可撤回。停止等待与发送，不会取消已经送到平台的消息；上游已受理的请求仍可能计费。撤回任务不能直接重试，需重新提出请求。
- `persona_canvas_conditions` 保存具体衣服、镜头、姿势、场景和避免内容，绑定当前角色、会话和请求。改变待确认要求后重新询问；确认后的条件写入实际提示词，并优先于冲突的状态变更。
- 每个人设最多 8 张参考图，可调整主图或逐张移除。接口按能力使用前几张，超过上限时明确显示提示；OpenAI GPT Image 与 Gemini 支持多图，NovelAI / 自定义适配器目前使用一张。
- 动态状态有效期可配置：默认服装持续保留，姿势和表情 30 分钟，场景 4 小时。到期后在下一次角色请求时恢复人设默认状态；0 表示持续保留。
- 主动消息加入持久化的机会时间与间隔波动，提醒角色接续近期话题。静默期结束或用户回复后重新开始未回复计数；发送前重新核对目标、时间窗与启用状态。
- 主动消息、照片和判断模型分开设置每日预算，所有目标和早安共用，管理员也受此预算约束。0 表示停用该类主动动作；模型与照片按尝试计数，消息按发送尝试计数，失败 / 取消不代表未计费。
- WebUI 总览增加首次配置检查；历史页增加动作诊断，包含拒绝、询问、条件、参考图、额度、生成和发送过程。
- 修复指定判断 Provider 缺失时回退开关无效，以及静默期结束后立即再次静默的问题。回退时不会把失效 Provider 的模型名传给当前会话模型。

拍摄条件会约束提示词与状态，但图像模型是否完整遵守仍需看实际结果；插件不会将计划画面当成已实际观察到的图像内容。

## 使用体验

- “给我拍张泳装照片”先由角色模型决定，可以答应、害羞地提条件、询问或拒绝。
- “拍远一点，可以吗？”只回复并保存待确认条件。用户明确回应后才可能拍照。
- 有效的拍摄条件确认支持“我要看”“听懂了”“发吧”“可以，发吧”，原生工具还支持 AI 根据上下文理解其他确认表达。确认已有条件时必须绑定当前请求；普通聊天里的短回应不会自动触发生图。
- “你穿泳装会害羞吗？”、“我不想自拍”、引用和假设讨论不会直接生图。
- “换成白色连衣裙”单独更新状态，不会自动拍照。换装条件与拍照条件分别保存。
- “再来一张”延续当前对话中的状态；“给我画一只猫”走普通场景绘图。
- 拍摄任务使用状态快照；失败不提交换装，较新的会话状态不会被旧任务覆盖，已切换的角色不会被旧任务改回。
- 用户再次确认同一组条件时查看已有任务，不重复创建或计费请求；失败需明确要求重试，撤回后需要重新提出请求。
- 拍照不设随机拒绝概率。是否愿意、姿势和镜头选择来自人格、拍摄偏好与对话。

## 安装与首次配置

推荐使用包含 Plugin Pages 的 AstrBot 4.25 或之后的 4.x 版本。4.17 是聊天接口兼容基线，该版本没有内嵌插件页面；旧版需开启独立兼容 WebUI，或升级 AstrBot 后使用内嵌页面。

将插件目录放在 `AstrBot/data/plugins/astrbot_plugin_persona_canvas/`，或在 AstrBot 插件管理中上传发行 ZIP。

Python 依赖列于 `requirements.txt`：aiohttp、Pillow、tzdata。AstrBot 安装插件时应安装依赖；手动复制时可在 AstrBot 使用的 Python 环境执行：

```shell
python -m pip install -r requirements.txt
```

1. 在插件详情中打开“随想画卷”管理页面。
2. 在“模型接口”添加绘画接口、手动填写模型名称或读取模型列表，设为默认接口。
3. 先做连接测试，再主动点击“生成测试图”验证真实出图能力；测试图可能产生接口费用。
4. 在“人设工作台”填写固定外观、画风与拍摄偏好，可绑定现有 AstrBot 人格并上传参考图。
5. 在“运行设置”选择聊天接入模式；业务设置由内嵌页面统一保存，重载会保留。
6. 在“生图工作台”预演角色决定，再提交拍摄请求并查看任务状态。

插件配置表只保留页面和独立服务器的生命周期选项。角色、接口、生成、配额、主动消息和早安设置都在内嵌页面中管理并立即生效。

## 聊天接入模式

### 原生工具（默认）

正常 AstrBot 聊天模型结合原人格和记忆决定是否调用：

- `persona_canvas_state`：角色愿意时更新衣服、姿势、表情和场景；支持语义请求或绑定条件的确认。
- `persona_canvas_conditions`：通过关键词或语义请求记录拍摄或换装条件，等待下一条明确确认，本轮不拍照或更新状态。
- `persona_canvas_photo`：AI 理解用户想要图片、且角色愿意时实际生图并发送；支持语义请求或绑定条件的确认。
- `persona_canvas_control`：用 `confirm` 确认当前约定，`revise` 修改条件并重新询问，`cancel` 撤回，`retry` 在用户明确要求时重试生成失败任务，`resend` 补发已保存原图。确认本身不会拍照，仍需调用照片或状态工具执行。

在 AstrBot 的函数工具设置中启用这四个工具；如果人格限制可用工具，也要允许它们。请求钩子补充视觉档案、当前状态、已约定条件与近期拍摄事实，保留原人格提示词。正常聊天不额外调用分类模型。

模型在 `request_summary` 简述本轮用户意图与上下文依据，即可提交不含固定关键词的请求。已有条件时，可先调用 `persona_canvas_control` 的 `confirm`，绑定视觉档案中的 `pending_conditions.request_id`，再调用照片或状态工具；也可在执行工具中直接填写 `confirmed_request_id`。后端重新读取条件并核对编号、会话、角色、类型和有效期。用户真正修改要求时，用 `revise` 或条件工具保存更新并重新询问；“就穿刚才约好的水手服拍吧”这类复述原条件的确认交给模型结合上下文判断。解释、询问和普通聊天保留仍有效的约定。

`revise` 的 `remove_fields` 可列出要移除的 outfit/camera/pose/expression/scene/avoid/notes 字段，`updates` 中空字符串或 null 同样表示移除约束。当前备注会改为新的约定说明，确认原条件时不允许删除字段。更新后产生新的请求编号，必须重新询问用户。

图片已生成而平台明确返回拒收时，任务记为 `delivery_failed`，可直接选择补发原图；超时、连接异常或发送中断记为 `uncertain`，须检查聊天记录后明确确认补发（工具参数 `confirm_uncertain=true`）。补发使用任务原图与原会话，不经过绘图接口。正在发送、已撤回或角色已改变的任务不能补发。历史 `sent` 默认返回已有结果；对于有原图和原会话的聊天、主动消息或配图任务，用户明确核对未收到后也可以恢复补发，避免旧版误记状态锁住原图。WebUI 会要求勾选核对确认，可能造成重复消息。

后台生成完成后，图片始终使用任务保存的原 UMO 调用会话发送接口，兼容流式与非流式文字请求已结束的情况。WebChat 类型通过平台元信息识别，平台实例 ID 可自定义。WebChat 缺少独立会话发送通道时不会退回旧事件；失败通知也遵守这个限制。

**WebChat 4.28.2 的回执限制：** 当前官方 [`Context.send_message()`](https://github.com/AstrBotDevs/AstrBot/blob/48ba71ad7477fc81c8aa99ad241f41ef5b1c0bfe/astrbot/core/star/context.py#L650-L713) 返回 True 仅表示找到平台，[WebChat 会话发送路径](https://github.com/AstrBotDevs/AstrBot/blob/48ba71ad7477fc81c8aa99ad241f41ef5b1c0bfe/astrbot/core/platform/sources/webchat/webchat_adapter.py#L86-L155) 没有持久化成功回执，还可能吞掉历史写入异常或遇到活动队列关闭竞态。插件调用原会话路径后会保守记为 `uncertain` / `delivery_evidence:unverified`，即使图片实际已出现也可能保持待确认；不能凭该返回值宣称实时投递或平台历史保存成功。请先查看原聊天及刷新历史，再决定是否补发。插件不改 AstrBot 核心或私有队列，不直接写平台数据库，无法承诺核心竞态下每次都能落库。其他平台的正常 None 返回保持兼容，`sent` 仅指发送调用完成，不保证终端收到。

模型的语义判断负责区分真实请求、讨论与叙述，后端另拦截明确撤回、纯引用和未唤醒群聊。相同条件通过原子预留领取一次任务，重复确认返回原任务状态；生成失败不会自动重新开放拍摄，需要用户明确要求后调用 `retry` 或后台重试。未填写语义参数的旧执行调用仍使用原有严格识别。

例如用户接续自拍话题说“让我见识一下今天这身打扮”，AI 愿意时可以这样调用；无需另加一轮分类模型，也不需要用户照模板重说：

```json
{"prompt":"sailor uniform, cheerful portrait, wide shot","request_summary":"用户接续自拍话题，请求查看今天服装的实际图片；我愿意展示。"}
```

角色同意并实际调用工具后，先完成无绘图网络请求的本地预检，检查选定接口、必填配置、参数映射、尺寸和真实参考图能力。OpenAI/Gemini 必须配置模型名；ComfyUI 的模型来自工作流，显示名可留空；自定义接口保留原有空模型兼容。明确无效时直接返回 `ok:false`，不创建执行任务、不领取条件执行编号、不消耗生成额度。修复配置后可在新一轮对话沿用仍有效的拍摄条件。

预检通过才创建后台任务，返回兼容的 `status:queued` 与 `phase:local_queued`、`submitted:false`、`upstream_accepted:false`，只表示本地任务已创建，等待后台提交，不能据此声称上游已经受理或正在生成。后台沿用选定接口名称并再次校验；同名接口的配置若被修改，会使用修改后的配置重新检查。完成后发送图片，避免生图耗时超过 AstrBot 的工具调用超时。模型可能理解错误或遗漏工具调用，插件不会凭文字答应补造授权。

原生后台及聊天重试失败后，优先调用 AstrBot 的独立会话发送通道通知；其他平台的通道不存在或没有会话来源时才使用原事件发送，WebChat 不退回旧事件。通知记录为 `accepted`（发送调用完成，终端送达未知）、`failed`（明确未发送）或 `uncertain`（投递结果未知），包含通道、脱敏错误及日志。WebChat 缺少确认时即使调用完成也记为 uncertain。结果不确定时不自动改用另一通道重复发送。通知状态独立于图片任务状态，已生成图片的发送问题保留原图，不重新标成生图失败。

`persona` 自拍默认采用角色档案中已启用的参考图库，不自动拿当前聊天附件替换角色形象。确实需要用户附件辅助拍摄时，模型显式填写 `use_message_image=true`；`edit` 模式会按需读取当前附件，也可选择上一张图片。普通图片聊天不会为了预备可能的生图而提前保存附件。

遇到只有文字“给你看自拍”却没有图片时，先到“生成历史 → 动作诊断”检查：如果显示“未调用拍照工具”，核对 AstrBot 是否启用 `persona_canvas_photo`、人格是否允许该工具，以及聊天模型是否支持工具调用；这条记录只能确认没有执行拍摄，不能单凭文字判断具体原因。不支持工具调用的模型可在“运行设置”改用兼容模式。如果显示“请求被拦截”，查看记录中的请求或条件检查原因。

### 兼容模式

供不支持工具调用的聊天模型使用。仅处理私聊或已明确唤醒机器人的消息，明确拍照/换装请求及有效条件确认才进入结构化角色决策。模型返回无效决策时停止执行，不降级为关键词直接生图。

兼容模式、命令与定时主动决策默认沿用该会话的聊天模型。在“模型接口”中可选专门的决策 Provider/模型；原生工具仍由 AstrBot 当前聊天模型决定。

聊天命令：

```text
/生图 给我画一片大海
/拍照 穿白色连衣裙，坐在窗边
/生图控制台
```

自拍命令同样经过角色意愿决定。后台“生成测试图”是管理员接口诊断，不经过角色同意，也不会改变聊天状态。

## 绘画接口

| 接口 | 实现 |
| --- | --- |
| OpenAI 兼容 | 原生 generations/edits，Base64 与实际图片内容验证；GPT Image 默认尺寸自动适配，显式不支持参数会给出错误 |
| Gemini | generateContent 文本和 inlineData 图片输入，识别真实 MIME 与最终图片部分 |
| NovelAI | 原生生成、ZIP/JSON 图片响应、真正 img2img；采样器、种子与负面字段。未实现 Character Reference/Vibe Transfer |
| 自定义 JSON | 路径、字段映射、参考图编码、额外参数、返回字段路径和独立连接端点 |

多图请求格式参照 [OpenAI Images Edit](https://developers.openai.com/api/reference/resources/images/methods/edit) 和 [Gemini 图像生成](https://ai.google.dev/gemini-api/docs/generate-content/image-generation)。兼容中转接口的实际能力可能低于原生模型，可在界面指定单张参考图。

“图片编辑”与“保持角色身份”不是同一个能力。参考图输入可以帮助保持形象，实际一致性仍取决于模型；不会因勾选能力开关就保证相同长相。

负面词的处理方式在“模型接口”中明确选择，保存的人设负面词与本次实际发送内容分别展示：

| 模式 | 行为 |
| --- | --- |
| `disabled` | 不发送负面词，也不追加到正面描述。OpenAI/Gemini 未指定新模式的旧配置默认采用此模式 |
| `natural_language` | 显式将避免约束写入正面自然语言描述，不表示存在独立负面通道；仅用于能理解这种描述的服务 |
| `field` | 发送到配置的独立负面字段。OpenAI 兼容和自定义服务需实际支持该字段，不能仅凭勾选开关判断；Gemini 原生适配器不接受此模式 |

NovelAI 始终使用原生负面字段。人设负面词和拍摄条件的 `avoid` 合并为负面内容，不把原始避免标签作为正面拍摄条件附加。负面约束是否完全有效仍取决于接口能力与实际模型输出。

独立字段使用 `negative_prompt_field` 配置；自定义请求的正面、负面、模型、参考图和参数路径不能相同或互为父子路径。保存配置时先检查映射冲突，避免负面词覆盖正面词。未知、空或损坏图片会报错。

自定义参数映射省略时保留已有设置，显式空对象 `{}` 表示不映射可选参数；“恢复默认映射”移除自定义覆盖并使用适配器默认值。请求摘要是当时的准备或请求阶段快照，`submitted:true` 表示已开始请求尝试，不代表上游已确认受理、成功生成或用户已收到；说明文字不改变该标记。较早版本没有阶段标记的记录会显示为早期记录。

绘图接口超时与运行设置中的任务生成超时均允许 5–600 秒，有效超时取两者较短值，聊天生成、工作台与接口测试图共用。请求摘要显示两项配置和实际生效时间；只增加接口超时不能延长更短的任务超时。

Gemini 工作台使用 `aspect_ratio` 选择宽高比，`image_size` 可选模型默认、`512`、`1K`、`2K` 或 `4K`；具体支持规格由模型决定。不显式覆盖时沿用默认参数，默认宽高用于推算比例，不当作固定像素尺寸发送。

返回图片 URL 默认不下载；启用后仅接受接口同源或显式允许的域名，并限制 DNS 地址、重定向与大小。推荐 Base64 或直接图片响应。

NovelAI 原生服务文档要求人工发起生成，适配器因此禁用定时主动照片和随机对话配图；手动聊天请求和工作台测试仍可使用。若启用自动配图，请选择支持自动任务的接口，例如本地 ComfyUI。

## ComfyUI 本地工作流

在“模型接口”中新建并选择 ComfyUI，地址填写 AstrBot 能访问的服务，例如 `http://127.0.0.1:8188`。AstrBot 在容器中时，`127.0.0.1` 指容器自身，请填写容器可访问的 ComfyUI 地址。模型栏仅用于工作流显示名称，实际 checkpoint、LoRA 与节点由工作流决定。

从 ComfyUI 导出 **API 格式** JSON，在页面选择文件导入，或直接粘贴到工作流编辑框。API 格式以节点编号为键，每个节点包含 `class_type` 与 `inputs`；编辑器的 `nodes` / `links` 格式需先在 ComfyUI 转为 API 格式。插件不安装工作流依赖的模型或自定义节点。

节点映射示例（编号和字段必须按自己的工作流修改）：

```json
{
  "prompt": "6.inputs.text",
  "negative_prompt": "7.inputs.text",
  "seed": "3.inputs.seed",
  "steps": "3.inputs.steps",
  "scale": "3.inputs.cfg",
  "sampler": "3.inputs.sampler_name",
  "width": "5.inputs.width",
  "height": "5.inputs.height",
  "reference": "10.inputs.image"
}
```

正面映射必填；其他映射按工作流能力填写，没有对应输入就删除该项。未映射参数沿用工作流原值，工作台不允许显式覆盖未支持的参数；负面词仅写独立负面映射，没有映射时不发送、不拼到正面。参考图映射应指向接受上传图片名称的输入，例如 `LoadImage.inputs.image`。输出节点可留空自动选择输出图片，或指定含图片输出的节点。

连接测试读取节点信息，不执行工作流；测试图会实际提交一次工作流。生成通过 `/prompt` 入队，轮询对应 `/history/{prompt_id}`，从同一服务的 `/view` 读取并验证图片。失败诊断保留任务编号和输出节点，不展示完整工作流与上传内容。取消只删除自身队列项，已开始执行的工作流可能继续运行；不会全局中断其他任务。

## 对话回复配图

在“聊天与主动消息”打开全局配图，再选择已发现的私聊或群聊，单独打开该聊天的配图开关并设置概率。`0%` 表示从不抽中，`100%` 表示每个合适的普通回复都提供一次机会；角色仍可决定跳过。全局默认概率只用于新发现的聊天，不覆盖已有逐聊天设置。可独立选择绘图接口（留空沿用默认接口）及同一聊天的冷却间隔。

抽中后额外调用当前会话的聊天模型，结合用户消息与已经生成的文字回复选择人设图、场景图或跳过，不要求用户出现“拍照”等关键词。生成使用已有视觉档案和参数，沿用普通生图额度与全局并发；命中后可能延迟该条回复。配图附加到文字消息，不另发重复台词；失败保留原文字，诊断记在后台。

显式图片请求继续走原来的角色工具与确认流程；已有待确认条件、命令、图片回复、插件工具已处理或流式回复时不叠加随机配图。配图不改变持续服装、状态、上一张照片或确认条件。生成过程中关闭配图、切换角色、收到新的聊天消息或改变条件时，旧图片不再附加。附加阶段仅表示图片已生成、交给回复链，平台是否发送或用户是否收到不能由此确认。

群聊的配图开关只对机器人实际生成的回复生效，未回复的群消息不会自行触发生图；群聊不启用私聊主动联系、早安或主动测试发送。

## 主动消息和早安

私聊收到消息后目标会自动出现，初始停用，由管理员启用。保存完整会话来源 UMO，按目标选择视觉角色。

安装并启用角色日程 0.3.1 或之后版本后，可在**日程插件**的运行设置打开“随想画卷联动”。联动遵守日程插件的总开关与对话白名单，使用当前会话的 AstrBot 人设；画卷中独立选择的视觉档案继续负责外观。开关关闭、没有安装日程插件或版本尚未提供联动接口时，保留原主动策略。

联动开启且适用于该对话时，当前活动资料会提供给主动决策和照片描述。忙碌时直接取消该次机会；日程尚未就绪或读取异常时保守跳过，不为这条主动消息额外生成日程、不进入待回队列。决策后与生图后重新核对日程及当前 AstrBot 人格、会话身份，变忙、联动启用范围改变或人设、会话、日期、活动改变时取消旧内容；当天已取消的早安不会等到空闲后补发。已生成的照片可能仍消耗绘图预算，取消会保留生成记录但禁止补发。发送前身份核对只读，不创建或覆盖画卷视觉会话；AstrBot 4.28 使用官方人格解析器匹配会话覆盖、默认人格与平台规则。

- 先检查目标开关、时间窗、时区、最近用户消息、最小发送间隔和连续未回复次数。
- 普通主动消息与早安共同遵守静默规则。
- 提供联系机会后由角色模型选择跳过、文字或照片。早安优先自然问候，不要求先有未完话题，愿意时可附照片。
- 在“聊天与主动消息 → 每日早安”可设置总尝试次数（1–5，默认 3）与跳过后重试间隔（60–3600 秒，默认 900）。只有本次模型返回暂时 `skip` 或尚未发送的技术失败可以重试，仍受时间窗、空闲、静默及每日模型预算限制。设为 1 次可保留一次机会的行为。明确 `refuse`、决策或生成期间发送条件改变、用户后来发来消息、平台拒收或发送结果不确定时不补发。发送前重新检查目标时区日期，不把前一天的内容发到下一天。成功发送后每天每个目标最多一次。
- 重试记录持久化，重启不会重置次数或间隔。升级前已经终结的旧 `skip` 记录保持原状，从下一天的新早安机会应用新规则。
- 参考近期聊天生成，不使用脱离上下文的固定破冰台词。
- 发送前再次检查是否收到新回复。生成期间用户回复会取消本次主动发送。
- 早安成功发送后当天不再领取；模型暂时跳过或发送前技术失败可限次重试，日程取消与明确拒绝保持终态。
- 目标独立执行，默认最多同时处理 3 个目标，可在主动联系设置调整；慢请求不阻塞其他目标，同一目标执行期间不会再次领取。
- 平台明确拒收图片保存为 `delivery_failed`，发送结果不确定保存为 `uncertain`，均不自动重新生图；已保存的图片可经任务或历史手动补发，结果不确定时先检查聊天记录。
- 主动发送依赖平台支持，QQ 官方与 OneBot 的限制不同，以实际发送结果为准。

## 数据和迁移

运行数据保存在 AstrBot 插件数据目录中：

```text
persona_canvas.sqlite3       设置、人设、会话、任务、配额、预算、发送、拍摄事实与临时资源租约
assets/                      参考图与生成图片
migration_backups/           旧 JSON 和数据库迁移备份
webui_token.txt              可选独立页面令牌
```

首次升级会备份并导入旧 `personas.json/settings.json/targets.json/history.jsonl/runtime.json`，保留原文件。读取失败或数据损坏时停止迁移，避免用默认值覆盖。旧 Persona Studio 目录也有兼容迁移。

0.5.5 将 SQLite schema 从 4 增量升级为 5，新增资源租约表；升级前创建数据库备份，不重建原有档案或会话。准备中的参考图由租约保护，绑定任务后由记录保护。后台清理未被角色、会话、任务、历史、动作或发送记录引用的过期孤立图片，未过宽限期的上传草稿继续保留。

API Key 仅保存在本地配置数据，不回传页面；保存时留空保留，清除需显式操作。导出为脱敏 JSON，资产列出名称，不包含图片二进制。完整备份需要同时备份数据库和 assets；运行时备份 SQLite 应使用 SQLite backup API 或先停用插件。

状态按平台会话、AstrBot 对话 ID 和当前视觉档案隔离；切换对话或角色不会继承另一会话的动态状态。成功额度按时区自然日计算，失败释放预留；管理员免每用户额度，全局并发仍生效。

## 兼容和验证

声明聊天兼容基线为 AstrBot `>=4.17,<5`。聊天工具、人格和会话接口按官方 v4.17.0 源码核对；内嵌页面目录已核对 v4.25/v4.27 的发现方式，并兼容当前官方 View/Page bridge。新 `astrbot.api.web` 不存在时，页面 API 延迟使用旧版 Quart 接入；后端 API 存在并不代表旧版 Dashboard 支持发现插件页面。

离线自动测试覆盖原生语义工具、条件请求编号与作用域、同条件原子预留、明确重试、角色切换后任务完成、参考图来源与租约、资源清理和 schema 迁移，以及负面通道、字段映射、真实请求摘要、有效超时、群聊元数据、撤回、照片事实、状态过期、预算持久化 / 并发和多图接口格式。0.5.7 增加 ComfyUI 工作流、逐聊天配图、当前会话模型、配图状态隔离与取消回归，0.5.9 增加早安提示、限次重试、静默拒绝、跨连接领取与跨午夜去重；0.5.10 增加真实适配器同步预检、原生排队语义及失败通知回归；0.5.11 增加 WebChat 结束请求后的原会话投递、真实临时 SQLite 历史和未知回执、旧 sent 恢复回归。0.5.1 的桌面及手机 7 页 WebUI 已用 Chrome 操作验证；0.5.11 的发送证据、旧 sent 与 uncertain 核对补发以及已有本地队列、失败通知说明、早安设置、工作流导入、节点映射、配图设置、实际请求诊断、补发、映射恢复和移动布局通过 Chrome 离线交互回归，使用模拟 bridge，未重复旧版全部七页的完整操作。本次实际测试数量和结果见更新日志。

不同 Dashboard 的页面发现能力与 QQ 主动发送能力需要实际部署联调。当前仓库测试使用隔离临时数据和 fake LLM/平台/图片 API，没有真实密钥调用和 QQ 实机发送。

```shell
python -m unittest discover -s tests -p "test_*.py" -v
node --check pages/canvas/app.js
python scripts/package.py
```

Windows 开发环境需要安装 `tzdata`，否则无法读取 IANA 时区。

打包命令在插件目录旁生成 `astrbot_plugin_persona_canvas.zip`，固定文件名方便 AstrBot 安装和升级，版本保存在 `metadata.yaml`。ZIP 只包含明确列出的源码、页面、说明与依赖，不包含运行数据、密钥或测试缓存。

本地离线 UI 验证：

```shell
python tests/preview_server.py
```

测试地址为 `http://127.0.0.1:39718`，固定测试令牌 `preview-test-token`。角色、接口、图片和平台调用全部是假数据，数据只存临时目录。输入包含“拒绝”或“条件”可演练对应分支，关闭后清理临时数据。
