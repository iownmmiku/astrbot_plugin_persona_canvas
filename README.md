# 随想画卷 Persona Canvas · 0.5.2

AstrBot 角色陪伴插件：沿用当前人格与聊天记忆，让角色先决定是否愿意拍照，再执行生图、换装、参考图编辑和主动消息。包含完整的 AstrBot 内嵌管理页面。

完整版本记录见 [更新日志](CHANGELOG.md)，每次更新同步维护。

## 0.5.2 修复

- “看看自拍”“看下你的自拍”“可以看一眼你的照片吗”等明确图片请求不再被漏掉；仅提到自拍、叙述、引用和讨论仍不会触发。
- 原生模式把本轮请求检查结果告知角色，强调愿意实际提供照片时必须调用工具，不能用文字描述代替发图；是否答应仍由角色决定。
- 动作诊断区分“未调用拍照工具”和“请求被拦截”，显示工具调用缺失或拦截条件，便于排查只有文字回复的问题。

## 0.5.1 新增

- 拍摄事实记录：原生异步照片的生成、失败、取消和发送状态会进入下一轮角色上下文；聊天记录仍由 AstrBot 管理。
- 聊天中说“别拍了”或后台点击“取消拍摄”即可撤回。停止等待与发送，不会取消已经送到平台的消息；上游已受理的请求仍可能计费。撤回任务不能直接重试，需重新提出请求。
- `persona_canvas_conditions` 保存具体衣服、镜头、姿势、场景和避免内容，绑定当前角色、会话和请求。改变待确认要求后重新询问；确认后的条件写入实际提示词，并优先于冲突的状态变更。
- 每个人设最多 8 张参考图，可调整主图或逐张移除。接口按能力使用前几张，超过上限时明确显示提示；OpenAI GPT Image 与 Gemini 支持多图，NovelAI / 自定义适配器目前使用一张。
- 动态状态有效期可配置：默认服装持续保留，姿势和表情 30 分钟，场景 4 小时。到期后在下一次角色请求时恢复人设默认状态；0 表示持续保留。
- 主动消息加入持久化的机会时间与间隔波动，提醒角色接续近期话题。静默期结束或用户回复后重新开始未回复计数；发送前重新核对目标、时间窗与启用状态。
- 主动消息、照片和判断模型分开设置每日预算，所有目标和早安共用，管理员也受此预算约束。0 表示停用该类主动动作；模型与照片按尝试计数，消息按发送尝试计数，失败 / 取消不代表未计费。
- WebUI 总览增加首次配置检查；历史页增加动作诊断，包含拒绝、询问、条件、参考图、额度、生成和发送过程。
- 修复指定判断 Provider 缺失时回退开关无效，以及静默期结束后立即再次静默的问题。回退时不会把失效 Provider 的模型名传给当前会话模型。

拍摄条件会约束提示词与状态，但图像模型是否完整遵守仍需看实际结果；插件不会将计划画面当成已实际观察到的图像内容。

## 使用体验

- “给我拍张泳装照片”先由角色模型决定，可以答应、害羞地提条件、询问或拒绝。
- “拍远一点，可以吗？”只回复并保存待确认条件。用户明确回应后才可能拍照。
- “你穿泳装会害羞吗？”、“我不想自拍”、引用和假设讨论不会直接生图。
- “换成白色连衣裙”单独更新状态，不会自动拍照。换装条件与拍照条件分别保存。
- “再来一张”延续当前对话中的状态；“给我画一只猫”走普通场景绘图。
- 拍摄任务使用状态快照；失败不提交换装，较新的会话状态不会被旧任务覆盖。
- 拍照不设随机拒绝概率。是否愿意、姿势和镜头选择来自人格、拍摄偏好与对话。

## 安装与首次配置

推荐使用包含 Plugin Pages 的 AstrBot 4.25 或之后的 4.x 版本。4.17 是聊天接口兼容基线，该版本没有内嵌插件页面；旧版需开启独立兼容 WebUI，或升级 AstrBot 后使用内嵌页面。

将插件目录放在 `AstrBot/data/plugins/astrbot_plugin_persona_canvas/`，或在 AstrBot 插件管理中上传发行 ZIP。

Python 依赖列于 `requirements.txt`：aiohttp、Pillow、tzdata。AstrBot 安装插件时应安装依赖；手动复制时可在 AstrBot 使用的 Python 环境执行：

```shell
python -m pip install -r requirements.txt
```

1. 在插件详情中打开“随想画卷”管理页面。
2. 在“模型接口”添加绘画接口、手动填写模型名称或读取模型列表，设为默认接口。
3. 先做连接测试，再主动点击“生成测试图”验证真实出图能力；测试图可能产生接口费用。
4. 在“人设工作台”填写固定外观、画风与拍摄偏好，可绑定现有 AstrBot 人格并上传参考图。
5. 在“运行设置”选择聊天接入模式；业务设置由内嵌页面统一保存，重载会保留。
6. 在“生图工作台”预演角色决定，再提交拍摄请求并查看任务状态。

插件配置表只保留页面和独立服务器的生命周期选项。角色、接口、生成、配额、主动消息和早安设置都在内嵌页面中管理并立即生效。

## 聊天接入模式

### 原生工具（默认）

正常 AstrBot 聊天模型结合原人格和记忆决定是否调用：

- `persona_canvas_state`：角色愿意时更新衣服、姿势、表情和场景。
- `persona_canvas_conditions`：记录拍摄或换装条件，等待下一条明确确认，本轮不拍照或更新状态。
- `persona_canvas_photo`：明确请求或确认拍摄条件后，角色愿意才调用。

在 AstrBot 的函数工具设置中启用这三个工具；如果人格限制可用工具，也要允许它们。请求钩子补充视觉档案、当前状态、已约定条件与近期拍摄事实，保留原人格提示词。正常聊天不额外调用分类模型。

工具调用还会检查用户请求、否定、引用、会话条件和本轮是否已执行。角色同意后创建后台拍摄任务，立即告诉聊天模型“正在生成”，完成后发送图片，避免生图耗时超过 AstrBot 的工具调用超时。失败会如实说明，发送结果不确定时不盲目重发。

遇到只有文字“给你看自拍”却没有图片时，先到“生成历史 → 动作诊断”检查：如果显示“未调用拍照工具”，核对 AstrBot 是否启用 `persona_canvas_photo`、人格是否允许该工具，以及聊天模型是否支持工具调用；这条记录只能确认没有执行拍摄，不能单凭文字判断具体原因。不支持工具调用的模型可在“运行设置”改用兼容模式。如果显示“请求被拦截”，查看记录中的请求或条件检查原因。

### 兼容模式

供不支持工具调用的聊天模型使用。仅处理私聊或已明确唤醒机器人的消息，明确拍照/换装请求及有效条件确认才进入结构化角色决策。模型返回无效决策时停止执行，不降级为关键词直接生图。

兼容模式、命令与定时主动决策默认沿用该会话的聊天模型。在“模型接口”中可选专门的决策 Provider/模型；原生工具仍由 AstrBot 当前聊天模型决定。

聊天命令：

```text
/生图 给我画一片大海
/拍照 穿白色连衣裙，坐在窗边
/生图控制台
```

自拍命令同样经过角色意愿决定。后台“生成测试图”是管理员接口诊断，不经过角色同意，也不会改变聊天状态。

## 绘画接口

| 接口 | 实现 |
| --- | --- |
| OpenAI 兼容 | 原生 generations/edits，Base64 与实际图片内容验证；GPT Image 默认尺寸自动适配，显式不支持参数会给出错误 |
| Gemini | generateContent 文本和 inlineData 图片输入，识别真实 MIME 与最终图片部分 |
| NovelAI | 原生生成、ZIP/JSON 图片响应、真正 img2img；采样器、种子与负面字段。未实现 Character Reference/Vibe Transfer |
| 自定义 JSON | 路径、字段映射、参考图编码、额外参数、返回字段路径和独立连接端点 |

多图请求格式参照 [OpenAI Images Edit](https://developers.openai.com/api/reference/resources/images/methods/edit) 和 [Gemini 图像生成](https://ai.google.dev/gemini-api/docs/generate-content/image-generation)。兼容中转接口的实际能力可能低于原生模型，可在界面指定单张参考图。

“图片编辑”与“保持角色身份”不是同一个能力。参考图输入可以帮助保持形象，实际一致性仍取决于模型；不会因勾选能力开关就保证相同长相。

OpenAI/Gemini 无独立负面通道时，将负面词编入自然语言避免约束。独立通道与自然语言约束在能力说明中区分。未知/空/损坏图片会报错。

返回图片 URL 默认不下载；启用后仅接受接口同源或显式允许的域名，并限制 DNS 地址、重定向与大小。推荐 Base64 或直接图片响应。

NovelAI 原生服务文档要求人工发起生成，适配器因此禁用定时主动照片；手动聊天请求和工作台测试仍可使用。若启用主动照片，请选择支持自动任务的接口。

## 主动消息和早安

私聊收到消息后目标会自动出现，初始停用，由管理员启用。保存完整会话来源 UMO，按目标选择视觉角色。

- 先检查目标开关、时间窗、时区、最近用户消息、最小发送间隔和连续未回复次数。
- 普通主动消息与早安共同遵守静默规则。
- 提供联系机会后由角色模型选择跳过、文字或照片。早安可以只有问候。
- 参考近期聊天生成，不使用脱离上下文的固定破冰台词。
- 发送前再次检查是否收到新回复。生成期间用户回复会取消本次主动发送。
- 已发送或角色选择跳过的早安当日不再领取；发送前失败有限重试。
- 发送结果不确定时保存为 `uncertain`，不盲目重发；先检查实际聊天记录。
- 主动发送依赖平台支持，QQ 官方与 OneBot 的限制不同，以实际发送结果为准。

## 数据和迁移

运行数据保存在 AstrBot 插件数据目录中：

```text
persona_canvas.sqlite3       设置、人设、会话、任务、配额、预算、发送与拍摄事实记录
assets/                      参考图与生成图片
migration_backups/           旧 JSON 和数据库迁移备份
webui_token.txt              可选独立页面令牌
```

首次升级会备份并导入旧 `personas.json/settings.json/targets.json/history.jsonl/runtime.json`，保留原文件。读取失败或数据损坏时停止迁移，避免用默认值覆盖。旧 Persona Studio 目录也有兼容迁移。

API Key 仅保存在本地配置数据，不回传页面；保存时留空保留，清除需显式操作。导出为脱敏 JSON，资产列出名称，不包含图片二进制。完整备份需要同时备份数据库和 assets；运行时备份 SQLite 应使用 SQLite backup API 或先停用插件。

状态按平台会话、AstrBot 对话 ID 和当前视觉档案隔离；切换对话或角色不会继承另一会话的动态状态。成功额度按时区自然日计算，失败释放预留；管理员免每用户额度，全局并发仍生效。

## 兼容和验证

声明聊天兼容基线为 AstrBot `>=4.17,<5`。聊天工具、人格和会话接口按官方 v4.17.0 源码核对；内嵌页面目录已核对 v4.25/v4.27 的发现方式，并兼容当前官方 View/Page bridge。新 `astrbot.api.web` 不存在时，页面 API 延迟使用旧版 Quart 接入；后端 API 存在并不代表旧版 Dashboard 支持发现插件页面。

104 项离线自动测试覆盖短图片请求、原生工具诊断，以及条件、撤回、照片事实、状态过期、预算持久化 / 并发和多图接口格式。0.5.1 的桌面及手机 7 页 WebUI 已用 Chrome 操作验证，原生页面桥接使用模拟 bridge 验证；0.5.2 的诊断标签更新完成 JavaScript 语法检查，未重复全部页面的浏览器验证。

不同 Dashboard 的页面发现能力与 QQ 主动发送能力需要实际部署联调。当前仓库测试使用隔离临时数据和 fake LLM/平台/图片 API，没有真实密钥调用和 QQ 实机发送。

```shell
python -m unittest discover -s tests -p "test_*.py" -v
node --check pages/canvas/app.js
python scripts/package.py
```

Windows 开发环境需要安装 `tzdata`，否则无法读取 IANA 时区。

打包命令在插件目录旁生成 `astrbot_plugin_persona_canvas.zip`，固定文件名方便 AstrBot 安装和升级，版本保存在 `metadata.yaml`。ZIP 只包含明确列出的源码、页面、说明与依赖，不包含运行数据、密钥或测试缓存。

本地离线 UI 验证：

```shell
python tests/preview_server.py
```

测试地址为 `http://127.0.0.1:39718`，固定测试令牌 `preview-test-token`。角色、接口、图片和平台调用全部是假数据，数据只存临时目录。输入包含“拒绝”或“条件”可演练对应分支，关闭后清理临时数据。
